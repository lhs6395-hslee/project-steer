이 Lab의 목표

Sonnet 4.6 (또는 Opus 4.7) 의 extended thinking 모드를 라우팅 / 평가 / 어려운 KB 합성 turn에 선택적으로 켠다. 모델이 답을 만들기 전에 reasoning token을 먼저 생성해 내부적으로 추론한다 — 정확도↑ / 토큰 비용↑ 트레이드오프.

2026-05 검증 근거 — boto3 1.43.15 service model.

  • bedrock-runtime.Converse.input.additionalModelRequestFields — free-form map. Anthropic 모델의 reasoning은 여기로 전달

  • bedrock-runtime.Converse.input/output.messages.content[].reasoningContent — content block type 으로 reasoning 토큰이 별도 분리 (요청/응답 양쪽 가능)

  • response.usage 에 input/output token 외 reasoning 토큰 카운트가 추가됨 (Anthropic provider)

실 호출 검증 (2026-05) — us.anthropic.claude-sonnet-4-6 + thinking={enabled, budget_tokens:2000} 로 직접 호출 → response 에 reasoningContent block + text block 둘 다 정상 반환. 4세대 Anthropic 모델은 bare ID 호출 불가 — 반드시 inference profile prefix (us. for us-west-2/east-1/east-2, global. for cross-region) 필요. anthropic.claude-sonnet-4-6 (prefix 없음) → ValidationException: on-demand throughput isn't supported. Retry with the ID or ARN of an inference profile.

2. Strands에서의 적용 — 4가지 패턴

2.1 패턴 A — BedrockModel 옵션 (가장 간단)

"""orchestrator.py — extended thinking 활성."""
from strands.models import BedrockModel

model = BedrockModel(
    model_id="us.anthropic.claude-sonnet-4-6",
    region_name="us-west-2",
    temperature=1.0,    # extended thinking 은 temperature=1.0 권장 (Anthropic)
    additional_request_fields={
        "thinking": {
            "type": "enabled",
            "budget_tokens": 4000,    # reasoning 토큰 상한
        }
    },
)

2.2 패턴 B — boto3 Converse 직접 호출

"""세밀 제어 — turn 마다 thinking on/off."""
import boto3

br = boto3.client("bedrock-runtime", region_name="us-west-2")

def invoke_with_thinking(messages: list, system_prompt: str, budget: int = 4000):
    resp = br.converse(
        modelId="us.anthropic.claude-sonnet-4-6",
        system=[{"text": system_prompt}],
        messages=messages,
        inferenceConfig={"temperature": 1.0, "maxTokens": 8000},
        additionalModelRequestFields={
            "thinking": {"type": "enabled", "budget_tokens": budget},
        },
    )

    # 응답 분리
    text_parts = []
    reasoning_parts = []
    for block in resp["output"]["message"]["content"]:
        if "text" in block:
            text_parts.append(block["text"])
        elif "reasoningContent" in block:
            # 디버깅 / observability 용도로 별도 보관
            reasoning_parts.append(block["reasoningContent"])

    usage = resp["usage"]
    print(f"input={usage['inputTokens']} output={usage['outputTokens']}")
    return "".join(text_parts), reasoning_parts

6. reasoning content 활용 — Observability

응답의 reasoningContent block 은 디버깅 / 평가에 유용. 그러나 사용자에게 노출 금지 (Anthropic 정책 + 일관된 UX). Lab-6 OTel span 의 attribute로만 보관:

from opentelemetry import trace
tracer = trace.get_tracer(__name__)

with tracer.start_as_current_span("orchestrator_thinking") as span:
    text, reasoning = invoke_with_thinking(messages, system_prompt)
    span.set_attribute("agent.thinking.tokens", sum(len(r) for r in reasoning))
    span.set_attribute("agent.thinking.preview",
                       (reasoning[0].get("reasoningText", {}).get("text", "")[:500]
                        if reasoning else ""))
    return text  # reasoning 은 사용자에 노출 X
